# 마이 북 (my_toon) 생성 — toon_create.py

현재 PC 에 보관 중인 웹툰 폴더/이미지를 분석해서 `my_toon_*` 테이블로 DB 화하고,
이미지를 기존 웹툰 서비스와 같은 형태(`D:\booktoon\{아이디}\{회차번호}\001.jpg ...`)로 복사합니다.

## 실행

```powershell
# 1) 폴더 구조 분석만 (복사/DB 없음) — 작업 전에 먼저 확인
python toon_create.py --TYPE 1 --name "도시정벌 1부" --path "D:\mynas\도시정벌 1부(01~12)" --dry-run

# 2) 신규 등록 (--bookid 없음 → 아이디 = 현재 일시 YYYYMMDDHHMMSS)
python toon_create.py --TYPE 1 --bookid "" --name "도시정벌 1부" --path "D:\mynas\도시정벌 1부(01~12)"

# 3) 이어하기 / 다시 반영 (같은 아이디로)
python toon_create.py --TYPE 1 --bookid 20261016093015 --name "도시정벌 1부" --path "D:\mynas\도시정벌 1부(01~12)"
```

| 옵션 | 설명 |
|---|---|
| `--TYPE` | 원본 폴더 구조 TYPE (아래 표). 기본 1 |
| `--bookid` | 비우면 신규 생성. 숫자 아이디를 주면 그 아이디로 등록/갱신 |
| `--name` | 제목 (`my_toon_info.title`) |
| `--path` | 원본 폴더 |
| `-o, --output` | 복사 루트 (기본 `D:/booktoon`) |
| `--dry-run` | 분석 결과만 출력 |

- 같은 크기의 파일이 이미 복사돼 있으면 건너뜁니다 → 중단돼도 같은 `--bookid` 로 다시 실행하면 이어서 진행.
- 회차 단위로 커밋합니다. 해당 회차의 이미지 행은 매번 새로 교체합니다.
- 실행이 끝나면 정보 파일 `D:\booktoon\{아이디}\{아이디}_{제목}.txt` 를 다시 씁니다
  (크롤러의 `279_나 혼자만 레벨업.txt` 와 같은 형식, 회차 목록은 `회차 | 장수 | 제목 | 원본 폴더`).
- PowerShell 5.1 은 `--bookid ""` 의 빈 문자열을 빼고 넘기므로, 값 없는 `--bookid` 도 신규 생성으로 처리합니다.

## 아이디 (bookid) 자료형

- 신규 아이디 = `YYYYMMDDHHMMSS` 14자리 숫자 (예: `20261016093015`).
- `BIGINT` 최대값 9,223,372,036,854,775,807(19자리) 안이라 문제 없음. `INT`(최대 21억, 10자리)였다면 넘침.
- 같은 초에 이미 있는 아이디면 1초 기다렸다가 다시 만듭니다.
- 사이트 웹툰 아이디(`toon_info.toon_id`, 5~6자리)와 자릿수가 달라 `D:\booktoon\{아이디}` 폴더가 겹치지 않습니다.

## 테이블 (book_sql/30_my_toon_테이블생성.sql)

실행 시 `CREATE TABLE IF NOT EXISTS` 로 자동 생성됩니다.

| 기존 | 신규 | 비고 |
|---|---|---|
| toon_info | my_toon_info | PK `my_toon_id`. 사이트 수집용 컬럼(source_url, rating 등) 제외, `src_type` / `src_path` / `image_root` / `total_image_cnt` 추가 |
| toon_episode | my_toon_episode | `episode_code` = `my-{my_toon_id}-{episode_no}`. `episode_title` = 원본 폴더명, `src_dir` 추가. `(my_toon_id, episode_no)` 유니크 |
| toon_episode_image | my_toon_episode_image | `org_url` 대신 `src_file` (원본 파일 경로) |

이미지 `page_no` 는 원본 파일명 숫자 순서대로 **1부터 다시 매깁니다**. 복사 파일명도 `001.jpg, 002.jpg ...` (확장자는 소문자).
원본 번호가 000 부터 시작하거나 중간에 빠져 있어도 뷰어에서는 연속된 순번이 됩니다. 원본 이름은 `src_file` 에 남습니다.

## 폴더 구조 TYPE

새 형태의 폴더가 나오면 TYPE 을 추가하고 여기에 기록합니다. (`toon_create.py` 의 `ANALYZERS` 에 함수 추가)

### TYPE 1 — 루트 / 회차폴더 / 이미지

```
D:\mynas\도시정벌 1부(01~12)\
  도시정벌 01\001.jpg, 002.jpg ...
  도시정벌 02\001.jpg, 002.jpg ...
  ...
```

- 루트 바로 아래 폴더 하나 = 회차 1개.
- 회차 번호 = 폴더명의 **마지막 숫자** (`도시정벌 01` → 1, `도시정벌 2부 01` → 1).
- 회차 폴더 바로 아래의 이미지(`jpg jpeg png gif webp bmp`)만 사용. `Thumbs.db` 등 다른 파일은 무시.
- 이미지 순서 = 파일명 숫자 순 정렬 (`2.jpg` < `10.jpg`).
- 분석 실패(중단): 폴더명에 숫자 없음 / 회차 번호 중복 / 회차 폴더 안에 하위 폴더 있음 → 새 TYPE 필요.
- 경고만(계속 진행): 이미지 없는 회차 폴더(건너뜀), 원본 파일 번호 빠짐, 빠진 회차 번호, 루트에 흩어진 이미지(무시).

분석 결과 (2026-10-16):

| 폴더 | 회차 | 이미지 | 특이사항 |
|---|---|---|---|
| `D:\mynas\도시정벌 1부(01~12)` | 12 (1~12) | 2,790 | 09회 원본이 `000.jpg` 부터 시작 (238장) |
| `D:\mynas\도시정벌 2부(01~16)` | 16 (1~16) | 2,735 | 09회 원본 `076.jpg` 없음 (170장). 회차 폴더마다 `Thumbs.db` 있음(무시) |

> work.txt 예시의 `도시정벌 1부(01~12)\도시정벌\도시정벌 01\001.jpg` 처럼 중간에 `도시정벌\` 폴더가 한 단계 더 있는 형태는
> 실제 폴더에는 없었습니다. 그런 폴더가 나오면 TYPE 1 분석이 "하위 폴더 있음" 으로 멈추므로 TYPE 2 로 추가합니다.
